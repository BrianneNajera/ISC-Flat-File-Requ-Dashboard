Rules/ Failure Modes

Please consider the following:

  1. Multiple Failure Points: Flat files introduce several potential failure points during the ingestion process. These include issues related to file format, encoding, and data consistency. Any failure at these points can disrupt the entire data pipeline.
  2. Manual Errors: Manually creating, editing, or managing flat files increases the risk of human errors. Typos, incorrect delimiters, and misaligned data can lead to inaccurate results and downstream issues.
  3. Limited Scalability: Flat files are not designed for large-scale data processing. As our data volumes grow, relying on flat files becomes increasingly inefficient and impractical.
  4. Maintenance Overhead: Managing flat files involves ongoing maintenance tasks such as monitoring, version control, and access permissions. These overheads can be minimized by adopting more robust data ingestion methods.

Save as CSV with UTF-8 encoding

The flat file must be saved as a .CSV file. In Excel, use Save As and select a CSV format with UTF-8 encoding.

FORMAT/ RULES:

  1. The flat file should be saved as a .CSV file.
    • File should not have duplicate rows. If duplicates exist only the first entry will be loaded.
  2. Use the Save As option from Excel to create a CSV file with UTF-8 encoding.
  3. Adhere to the following specifications.
    • File Compression: The file should not be compressed.
    • Record Delimiter: Use a new line (\n) as the record delimiter.
    • Field Delimiter: Separate fields using a comma (,).
    • Quoting: Enclose fields containing commas within double quotes (") to avoid parsing issues.
    • Escape Character: Use a backslash (\) to escape double quotes within field values.
    • Header Row: Include a header row with column names.
    • Encoding: Save the file with UTF-8 without BOM.
    • Single Sheet: Keep only one sheet per workbook.
    • Password Protection: The file should not be password protected.
    • Numeric Fields: Remove thousand separators (e.g. 1,456 to 1456).
    • Currency Symbols: Remove any currency symbols (e.g. $) and M signs from amount fields.
    • Percentage Fields: Remove the percentage sign (e.g. 13.6% to 13.6).
    • No Empty Rows: Remove the entire row if the data has been deleted.

NAMING CONVENTIONS:

  • For the XREF use case, follow the naming pattern: EDW_AERO_ISC_*
    • Example: EDW_AERO_ISC_XREF_NON_SAP_SITES.csv

FINAL NOTES:

  • Confirm the file name and format are accurate.
  • Verify the file is uploaded to the correct folder.
  • Ensure the new file contains all required information, not only the updated data.
    • Use the most current version of the file.
  • Confirm that the file is uploaded to the folder path in the example below.

Defect Reports

We validate some flat file uploads by cross-referencing plant and material master data. The reports below include defect indicators that flag values in the flat files that do not match the master documents, and when these discrepancies occur, the system prevents the files from being uploaded. The defect log itself also provides a generalized explanation of how each failure is triggered.

Once files are successfully loaded, these indicators must be reviewed to ensure no records have been dropped. To support efficient troubleshooting, an additional column identifies exactly which entries contain defects, enabling teams to quickly locate and correct misaligned data.

Attention: Please check the defect logs if they exist for the flat file being uploaded.

Recommendations:

  • Avoid using flat files for data ingestion.
  • Explore other methods: direct database connections, API-based ingestion, or streaming pipelines.
  • For Flat File use follow set-up guidelines, proper file naming conventions, directory structures, and automated processes.
